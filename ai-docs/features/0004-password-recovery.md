# 0004 — 邮箱验证码找回密码

## 1. 目标、触发与范围

- 用户请求：“提交push，下一步是把找回密码做了，需要邮箱验证，然后确认新密码”；随后明确选择学员和教练共用、使用邮件验证码。
- 关联已批准的[实施计划 0004 revision 1](../implement-plan/0004-password-recovery.md)及 [TODO-0008](../todo/0008-password-recovery.md)。
- 忘记密码的已验证学员或教练可以在登录页申请验证码，验证后两次输入新密码，完成后用新密码重新登录。
- 本次包含找回入口、邮件验证码、确认新密码、旧密码与已登录会话失效、必要的限流及邮件失败恢复。
- 本次不包含公开教练注册、修改已登录账号的密码、短信、第三方身份提供商、生产部署或新付费资源。
- v1 只作业务参考；沿用 v2 的 GEER 蓝色响应式页面、已有 Gmail/Mailpit SMTP 配置、PBKDF2 密码策略及 Spring Session，不导入 v1 数据/密钥。

## 3. 业务规则与未决事项

- 角色：学员与教练共用。仅已验证邮箱的账号产生有效验证码；请求入口不公开账号是否存在/已验证。
- 用户已批准 revision 1 的参数：8 位数字验证码，10 分钟有效；同一账号新申请使旧码失效；每次验证码最多 5 次错误尝试，核验入口同 IP 每 15 分钟最多 30 次；同 IP 每小时最多申请 10 次、同邮箱每小时最多申请 3 次，60 秒内不重复发新码；验证码通过后，核验时所在的服务端会话获得最多 5 分钟的重设授权，完成时验证码也必须仍有效。
- 重设授权仅用于一次密码更新，不等于登录。新密码不得与当前密码相同；沿用已批准的 8–128 Unicode 字符、无强制字符类别规则。前后端都检查“新密码/确认新密码”一致，服务端为最终依据。
- 成功后所有该账号旧登录会话对后续受保护请求失效，当前重设会话也被清理；必须用新密码重新登录。请求找回、验证验证码本身不修改密码。

| 起始状态 | 用例/操作者 | 前置条件 | 目标状态 | 失败与副作用 |

## 4. 模块、端口与依赖

- identity 拥有账号、找回挑战和找回邮件任务；frontend 只负责展示和提交，不能根据客户端状态自行授权。Spring Session 表仍属身份基础设施，不作为跨业务模块数据。
- 入站用例：申请验证码、核验验证码、确认新密码、查询账号凭据版本。验证成功的结果供 Web adapter 写入服务端 Session 授权；用例不接触 Servlet、Cookie 或 Spring Security。
- 出站端口：找回记录/限流、验证码编解码、密码散列、邮件任务/发送、时间；MySQL、SMTP、Session 机制由 adapter/bootstrap 承担。保留现有 identity 对外入站契约，必要时扩展登录结果携带仅服务端使用的凭据版本。
- domain 负责验证码形状、密码长度与确认规则；应用层编排锁、状态、事务、角色一致性。跨模块调用不适用。
- 涉及项目契约 WORK-02/08/09、ARCH-01~09、DEP-01~07、DATA-01、SEC-01~03、API-01~04；相关 [ADR 0001](../decisions/0001-v2-baseline.md)。预期无需架构例外，六类违规基线保持 0。

## 5. API 与前端契约

以下路径和错误语义已按 revision 1 实现；公开 POST 均需要现有 CSRF token，不要求已登录。成功与错误沿用 v2 JSON/Problem Details，不返回验证码、密码、摘要或授权内部值。

| Method / Path | 身份与资源权限 | 输入 | 输出 | HTTP/业务错误 | 幂等行为 |
|---|---|---|---|---|---|
| POST /api/auth/password-recovery/request | 访客/登录者 + CSRF | `email` | 统一“若账号可找回，请查收验证码” | 400 格式错、429 限流、503 基础设施故障；账号状态不改变响应 | 60 秒内同邮箱不新增验证码/邮件 |
| POST /api/auth/password-recovery/verify | 同一浏览器会话 + CSRF | `email`, `code`（8 位字符串） | 验证成功提示；服务端 Session 获短时授权 | 400 格式错、410 无效/过期/锁定、429 来源限流 | 有效码可在消耗前重新核验；不延长原到期时间 |
| POST /api/auth/password-recovery/complete | 获授权的同一会话 + CSRF | `newPassword`, `confirmPassword` | 重设成功提示 | 400 密码不合法/不一致/等于当前、410 授权/码失效 | 仅成功一次；重复提交不再次改密码 |

- 登录页增加“忘记密码”；申请页 → 输入验证码页 → 两次输入新密码页 → 成功返回登录，保留 GEER 蓝色桌面与手机布局。提供重发/重新申请、返回登录、加载中与可读错误提示；验证码输入保留前导零，移动端显示数字键盘。
- 初次申请的界面文案保持中性，不因不存在/未验证邮箱改变。验证码失效显示重新申请入口；成功后清空密码、验证码和客户端账号状态，不自动登录。
- 不把验证码、授权或密码放入 URL、localStorage、sessionStorage、日志或埋点；验证码只在当前页面内存，授权只在 HttpOnly 服务端 Session。缓存/受保护数据在密码重设后清理。
- 沿用同源 `/api`、HttpOnly/SameSite Cookie、正式 HTTPS 的 Secure 属性及 CSRF；找回接口仅在安全配置中按精确路径公开。已有邮箱验证链接不改变。

## 6. 数据、事务与并发

- 追加 Flyway V3：账号增加 `credential_version BIGINT NOT NULL DEFAULT 0`；新增 `identity_password_reset`（账号、验证码摘要、到期、错误次数、已消耗/失效时间）及 `identity_password_reset_mail_task`（投递状态/领取租约/重试信息），带 FK 和领取/账号索引。保留 V1/V2 原文件与既有账号摘要。
- 验证码由服务端密钥、用途标签及随机挑战 ID 派生；数据库仅保留摘要，邮件任务可重建待发的码，不保留明码。找回用途与注册验证 token 隔离；密钥轮换使未使用码失效。
- 申请、核验与完成按 `identity_account` 固定行先加锁，再读取/更新挑战；条件更新保证旧码、并发核验和双提交不能越过次数或一次性规则。错误尝试在失败响应前持久提交；密码摘要、`credential_version+1`、挑战消耗在同一事务原子完成。
- 每个已认证 Session 在登录时记录当前凭据版本；每次受保护请求经身份入站用例与数据库当前版本比较，不匹配或缺版本即拒绝、清理会话。部署前旧 Session 无版本，首次访问会要求重新登录。并发中已进入处理的请求按事务提交时序处理；重设提交后的新请求必须拒绝旧 Session。
- 不导入 v1 数据。V3 属不可假定可逆的 DDL；部署前备份，应用回滚须与迁移版本协调。

## 7. 异步任务与外部依赖

- 找回挑战与邮件任务同一事务提交；沿用现有同进程轮询与 SMTP 配置，使用独立找回邮件主题与文本。领取、过期租约、失败退避和重试遵循现有验证邮件队列模式；发送前检查码仍有效，旧/已消耗任务跳过。SMTP 故障不把任务标为已送达，页面只说明“若可找回将发送”。
- 重复投递可能发生在 SMTP 已发送但成功状态写回前；验证码仍由数据库一次性消耗。新申请与已领取任务竞争时，可能晚到一封旧码邮件；旧码不能完成重设，邮件提示使用最近一次申请。
- 复用已配置的 Gmail SMTP 或本地 Mailpit，不新增云邮件账号/付费资源。S3、媒体任务不适用。
- 安全依据：[OWASP Forgot Password Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)、[OWASP Session Management Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)。

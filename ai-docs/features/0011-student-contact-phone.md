# 0011 — 首次预约前填写联系电话

## 1. 目标、触发与范围

revision 2 已完成本地实现/验收：用户不希望手输国家区号，改为选择国家前缀、后面输入号码，并询问现成组件。配对[计划 revision 2](../implement-plan/0011-student-contact-phone.md)采用默认加拿大 +1，现成 react-phone-number-input 3.4.18 搭配原生国家下拉，前端组合完整号码。revision 1 已完成的联系方式/权限契约和证据保留；2026-10-06 用户“批准”当前 revision 2，本地实现和验证已完成；随后用户要求“提交推送”，授权将本次改动推送 main，通过既有流水线交付。

- 用户提出：学员留下电话，线上预约后即使尚未加微信，教练也能主动联系。随后明确：“第一次预约前必填，然后要让他知道留电话是为了联系确认”。
- 用户已于 2026-10-06 回复“批准”，确认[计划 0011 revision 1](../implement-plan/0011-student-contact-phone.md)的本地实现和验证范围；随后回复“提交”授权本次本地 Git commit，未授权 push 或生产发布。
- 在学员约课页“申请信息”中填写联系电话，紧邻字段说明：**“用于教练联系你、沟通并确认预约。”** 保存一次，后续预约自动带入，可修改；教练在预约申请卡片查看电话，手机端可点击拨号。
- 包含本人电话读写、新预约服务端前置条件、教练授权查看、手机布局与既有账号/预约兼容。
- 注册和登录仍按 [0002](0002-student-identity.md)；预约、确认、拒绝和取消按 [0006](0006-post-login-booking-home.md)。不在注册或登录时要求电话，不引入短信验证、自动拨号、电话通知或 v1 数据导入。

## 3. 业务规则与未决事项

revision 2 将“手动输入完整国际号码”改为“选择国家/地区 + 输入号码”；无已存值时默认加拿大，选项显示中文国家名与区号，优先加拿大/美国/中国，其余使用组件国家列表。提交/存储仍为完整 + 和数字，数据库/API/基本格式不变，不单独持久化国家选择。粘贴完整号码可识别区号，+1 默认加拿大；未知旧格式保留而不猜造国家或改写。用途、权限、首次预约必填及教练 tel 都保留。

选型与具体实施已获 revision 2 批准；无其他阻塞业务问题。下面国际号码格式是保留的 API/存储规则；当前界面由国家选择与号码自动组合。

- 电话是学员当前联系方式，属于账号资料；预约不保存电话快照。本人修改后，教练查看该学员已有预约时获得最新电话，以便实际联系。
- 空电话只允许存在于尚未填写的旧/新账号。保存接口不接受清空；创建新的预约要求账号已有合法电话，不要求每次手动输入。旧预约的处理与读取不补加此前置条件。
- 输入含国家区号，例如 `+1 416 555 0123`、`+86 138 0013 8000`；允许空格、括号和连字符，规范化后须为 `+` 加 7–15 个 ASCII 数字，首位数字非 0。原始输入上限 64 字符。此为本功能基本格式约束，不检查运营商、真实归属或是否能拨通，不假设裸号码属于哪个国家。
- 唯一教练只能通过本人预约查看相关学员电话；公开主页、学员预约列表和登录身份响应不增加电话。电话不放 URL 查询参数、持久化浏览器缓存、分析事件或应用日志。
- 联系用途的说明始终放在字段旁；不暗示填写电话即代表预约已确认。预约仍为 PENDING，由教练另行确认。

| 起始状态 | 用例/操作者 | 前置条件 | 目标状态 | 失败与副作用 |
|---|---|---|---|---|
| 无电话 | 保存/本人学员 | 有效 Session、CSRF、合法电话 | 已保存电话 | 失败不创建预约 |
| 已有电话 | 修改/本人学员 | 同上 | 新电话 | 仅更新电话；并发保存以最后提交值为准 |
| 无新申请 | 申请/本人学员 | 已保存电话及既有课程、时段、雪场规则 | PENDING | 预约失败不撤销独立保存的电话 |
| 已有预约 | 读取或处理/有权角色 | 既有预约授权与状态规则 | 按 0006 | 不因旧账号没有电话而阻止处理 |

|---|---|---|---|---|
| 保存/修改与教练显示 | 保存当前账号电话，约课区可单独修改；教练预约卡片可拨号 | 资料/API/前端 | 否 | 2026-10-06 用户“批准”revision 1 |

## 4. 模块、端口与依赖

revision 2 只新增前端 MIT 依赖 react-phone-number-input 3.4.18（已精确安装并锁定传递依赖），包装成区号选择/号码输入；当前 React 19.3 版本不升级。后端仅调整格式错误说明，identity/bookings 端口、领域格式规则及六类零基线不变，无新 ADR 或云服务。以下为保留的模块契约。

- identity 拥有 `identity_account` 电话列、纯 Java `ContactPhone` 规则和 `StudentContactOperations` 入站用例：本人查询、本人保存、内部教练批量查询。
- `StudentContactService` 从 actor 校验角色与本人身份；Web 层用独立请求/响应 DTO 映射入站端口。扩展 `IdentityStore` 的电话查询/更新能力，不扩展注册 command、`AccountView` 或密码更新语义。
- bookings 新增消费者出站端口 `BookingStudentContacts`，通过 `adapter.out.module` 调用 identity 公开入站端口；application 不依赖 identity service、domain 或数据库适配器。
- 新申请在幂等重放判断后、获取排课锁之前检查当前学员电话。教练查询先验证角色和预约归属，再从已授权结果提取学员 ID，按每页最多 50 条批量读取电话；内部批量端口也校验 COACH 角色且不开放任意 ID 的 HTTP 接口。
- 教练查询返回专用用例投影及 Web DTO，保持原有扁平预约 JSON 并附加 `studentPhone`；电话不进入预约持久化模型。学生响应维持原契约。联系方式不混入邮件地址查询端口。
- 适用 WORK-02/06/09/11、ARCH-01~09、DEP-01~07、DATA-01、SEC-01~03、API-01~04、FE-01、BOOK-07。架构例外：无；保持既有零违规基线与 [ADR 0001](../decisions/0001-v2-baseline.md)，不新增基础架构 ADR。

## 5. API 与前端契约

revision 2 前端示例为 `[加拿大 +1 ▼] [416 555 0123]`，不要求学员手输 +1；提交仍为表中完整号码 JSON，服务器不会将裸号码猜为某国家。国家下拉/号码输入在手机保持清楚分隔并适应宽度，保留紧邻用途说明；原始手输区号提示替换为“选择国家/地区后填写电话号码，保存后下次预约会自动填入”。基本格式服务端错误文案改为“请填写有效的联系电话。”。不新增 API 或数据字段，原读写/申请/电话显示行为保留。

| Method / Path | 身份与资源权限 | 输入 | 输出 | HTTP/业务错误 | 幂等行为 |
|---|---|---|---|---|---|
| GET `/api/student/contact` | STUDENT，仅本人 | 无 | `{ "phone": null }` 或规范化电话 | 401/403；读取失败 5xx | 只读 |
| PATCH `/api/student/contact` | STUDENT，仅本人 + CSRF | `{ "phone": "+1 (416) 555-0123" }`；无目标账号参数 | 200 `{ "phone": "+14165550123" }` | 400 格式/缺值；401/403；存储失败 5xx | 同值重复保存不增加记录 |
| POST `/api/bookings`（扩展前置条件） | STUDENT，仅本人 + CSRF | 既有课程、时段、雪场与 Idempotency-Key | 既有 201/200 Booking | 新请求缺电话 400：“请先填写联系电话，用于教练联系并确认预约”；其余沿用 0006 | 先查既有幂等结果，再检查电话；指纹不包含独立账号资料 |
| GET `/api/coach/bookings`、`/api/coach/bookings/{id}` | COACH，仅本人预约 | 既有分页/状态或预约 ID | 既有扁平预约字段 + `studentPhone: string/null` | 沿用 0006；电话查询故障返回失败，不伪装为未填写 | 只读 |

- 沿用 v2 明确 JSON 成功响应和带 HTTP status 的问题响应。确认/拒绝接口继续原有响应；前端合并结果时保留当前卡片电话，之后用教练查询刷新。
- 在“申请信息”中增加标签“联系电话（必填）”、`type=tel` / `autocomplete=tel`、示例、用途说明及字段错误；已有电话自动带入，提供“保存电话”轻量按钮，未填写时“申请预约”也会先保存再申请。输入与操作在手机纵向排列，避免压缩申请信息。
- 电话读取独立于课程/时段读取。初次读取未完成或失败时，课程可浏览，电话保存/申请等待读取成功；提供重试，不用空白值覆盖未知的已存电话。普通预约刷新不覆盖尚未保存的输入。
- 电话保存成功后才允许本次预约请求；电话未变化可直接申请。两个操作串行、提交时禁重复操作。预约失败时说明电话已保存且申请未成功；网络结果不明时提示按同一请求重试，不宣称预约一定未创建。
- 电话状态只在当前账号内存保存，退出、401 或切换账号清理；复用同源 Cookie/CSRF，无新增 CORS 或认证凭据。

## 6. 数据、事务与并发

- 追加 `V11__student_contact_phone.sql`：`identity_account.contact_phone VARCHAR(16) NULL`，存 `+` 和最多 15 位数字；不建索引/唯一约束，同一个家庭可共用电话。既有 V1–V10 不变。
- 历史账号初值 NULL，无猜测回填；教练账号不开放电话保存。更新仅修改本学员电话，不改姓名、邮箱、验证状态、密码或 credential version。
- 联系电话保存是独立的短事务，单行 UPDATE 保证完整值写入；不锁排课记录。前端等保存提交后再申请；bookings 的 READ_COMMITTED 事务通过端口读取已提交电话，不新增 identity 行锁，保留排课锁顺序。
- 电话不能通过此接口清空，因此并发修改仍保持新申请的非空前置条件；并发保存最后提交值生效。预约唯一约束、幂等键和通知同事务保障沿用现有实现。
- 追加可空列使上一版本忽略它；应用回退保留 V11 和电话数据，不删除列或修改 Flyway 历史。回退版本不会强制填写电话，需如实记录；生产迁移前沿用现有数据库备份流程。

# TODO-0012 — 本地教练新增雪场和发布日程无响应

## 1. 来源与关联

- 发现于：2026-10-01 用户反馈“新增雪场那个按钮和整天覆盖并发布那个按钮按了没用”；本地运行环境与页面交互调查。
- 相关功能/计划：[0006 功能](../features/0006-post-login-booking-home.md)、[0006 实施计划](../implement-plan/0006-post-login-booking-home.md)。

## 2. 背景

教练在可用时间页面先新增雪场，再点选日期并发布日程。本地 5173 开发页面使用 8080 后端；8088 是容器前端。首次调查时本地容器镜像仍是 2026-09-30 的旧版，后端包只有 V4。更新容器后用户仍报告同样症状；进一步在局域网 HTTP 地址的真实浏览器中发现 `crypto.randomUUID` 不存在，填好内容后两个按钮都会在发请求前抛错。

## 3. 问题与影响

旧容器无法处理新接口。更新容器后，通过局域网地址访问时，有效输入的写入动作仍在客户端生成请求键时中断，页面没有请求和可见错误。新增雪场失败只在页面顶部提示、空名称被浏览器原生校验拦住；发布按钮在缺少雪场、日期等条件时直接禁用，也使问题难以定位。

## 4. 期望结果

本地前后端运行同一已批准版本。教练新增雪场和发布日程时，按钮附近立即显示成功或失败；缺少输入条件时说明原因，已有输入在失败后保留。

## 5. 完成判定

- 本地容器提供当前前后端页面与接口，健康检查通过；测试教练登录后能访问雪场和覆盖接口。
- 通过局域网 HTTP 地址打开 5173 与 8088，填写有效输入点击两个按钮，能观察到请求被发出与表单旁的结果提示。
- 有效输入的雪场创建与日程发布通过真实 MySQL API 回归；页面交互测试覆盖成功、缺少输入和接口失败的就地反馈。
- 缺少必需输入时点击按钮能看到可执行的提示。

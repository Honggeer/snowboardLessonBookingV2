# TODO-0009 — IDEA 本地数据库凭据不易核对

## 1. 来源与关联

- 发现于：用户 2026-09-29 提供的 IDEA 后端启动日志，MySQL 返回 `Access denied for user 'snowboard_v2'@'172.18.0.1' (using password: YES)`。
- 相关功能/计划：[身份功能 0002](../features/0002-student-identity.md)、[实施计划 0002](../implement-plan/0002-student-identity.md)。

## 2. 背景

IDEA 使用本机映射端口连接 Docker MySQL。当前 Docker MySQL 正常运行；`deploy/.env` 中的数据库密码可通过 `127.0.0.1:3307` 登录。IDEA 私有启动配置未保存在可读取的项目文件中，实际传入值尚未核实。

## 3. 问题与影响

本地后端启动时被数据库拒绝认证，身份服务与 Flyway 无法启动。现有配置示例的说明文字可能被误当作实际环境变量值；用户难以判断应该核对哪一侧的凭据。确切的 IDEA 配置差异仍待用户本机查看。

## 4. 期望结果

本地开发说明明确指出 IDEA 应使用哪组数据库连接信息、如何在不公开密码的情况下核验连接，以及为什么不应通过随意修改现有数据卷的容器环境变量来解决。

## 5. 完成判定

- 文档说明 IDEA 与 Docker MySQL 的连接参数及密码来源。
- 提供可在本机交互输入密码的只读连接检查方式，并说明既有数据卷的密码不会随环境变量自动变化。

## 6. 未决事项与状态记录

- 需要用户澄清的问题：IDEA 当前实际传入的 `DB_PASSWORD` 值是否与 `deploy/.env` 一致；不要在对话中发送密码。
- 2026-09-29：OPEN；根据用户启动日志记录问题。
- 2026-09-29：DONE；确认 `.env` 凭据可从本机映射端口登录，更新[后端本地开发说明](../../backend/README.md)。用户 IDEA 启动结果仍需用户本地按说明复核。
